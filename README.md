# Quire

**Agent-native presentations in one portable file.**

[Open Quire](https://quiredeck.com) · [Format reference](SPEC.md) ·
[Contributing](CONTRIBUTING.md)

Quire turns structured, Markdown-shaped source into polished slide decks. It is
designed for coding agents: decks are easy to create, review, and revise as
text, while Quire handles the visual layout.

Each `.quire` file bundles the deck source and its images. Open it in the web
viewer or install Quire as a desktop app. No account or upload is required.

## Features

- **Agent-first authoring** with a focused presentation format.
- **One-file decks** that package source and images together.
- **Live preview** when a deck changes on disk.
- **Built-in validation** for source, assets, and slide overflow.
- **Local rendering** to contact sheets or individual slide images.
- **Standalone export** for sharing a deck as HTML.

## Quick start

1. Install the Quire skill for GitHub Copilot:

   ```bash
   gh skill install markgar/quire quire --agent github-copilot --scope user
   ```

2. Reload skills with `/skills reload`, then ask Copilot to create a deck:

   > Create a 10-slide Quire deck explaining how Apollo 11 reached the Moon.
   > Research accurate facts, cite sources, and include a timeline, process
   > diagram, metrics, and a chart. Save it as `apollo-11.quire`.

3. Open [quiredeck.com](https://quiredeck.com), choose the generated `.quire`
   file, and present.

## Install the app

On Chrome, Edge, and other Chromium browsers, choose **Install Quire** to add
Quire as a desktop app. It opens decks in separate windows, opens `.quire`
files from your computer, and works offline.

Installation is optional. If **Install Quire** is unavailable, use your
browser's install icon or menu.

## The Quire skill

The skill teaches your agent how to design and author Quire presentations. It
also includes a CLI so the agent can work with `.quire` files reliably instead
of treating them as unstructured text.

With the skill installed, your agent can:

- create a complete presentation from a prompt;
- inspect and revise individual slides;
- add and manage packaged images;
- validate the deck and check every slide for overflow;
- render previews for visual review;
- export standalone HTML for sharing.

The skill uses commands like these behind the scenes:

```bash
node src/cli.js create deck.quire --title "Quarterly review" --theme dark
node src/cli.js slides replace deck.quire 1 --content "# Quarterly review"
node src/cli.js assets add deck.quire chart.png images/chart.png
node src/cli.js validate deck.quire
node src/cli.js fit deck.quire
node src/cli.js render deck.quire deck-contact-sheet.png
node src/cli.js out.html deck.quire
```

Deck edits are validated before they replace the original file. A failed edit
leaves the existing deck unchanged.

## Development

Quire requires Node.js 22.

```bash
npm install
npm run check
npm run serve
```

Then open:

- [Example deck](http://localhost:8931/quire.html?deck=test/fixtures/trusting-the-suite.quire)
- [Visual language reference](http://localhost:8931/quire.html?deck=test/fixtures/visual-language.quire)
- [Local deck picker](http://localhost:8931/quire.html)

`npm run check` runs strict type checking, rebuilds the hosted app, and runs the
test suite. The source is plain JavaScript with `// @ts-check` and JSDoc types.

The opt-in skill test makes a live agent call and is kept separate from the
default test suite:

```bash
npm run test:skill
```

Set `QUIRE_SKILL_TEST_KEEP=1` to keep its temporary project or
`QUIRE_SKILL_TEST_MODEL=<model>` to select a model.

## Project structure

| Path | Purpose |
|---|---|
| `skills/quire/` | Canonical parser, renderer, package tools, CLI, and Copilot skill |
| `src/` | Browser app modules and CLI entry point |
| `quire.html` | Generated, deployable app |
| `SPEC.md` | Detailed format and viewer behavior reference |
| `test/` | Conformance, browser, package, CLI, and visual regression tests |
| `tools/` | Build, development server, and fixture utilities |

`quire.html` is generated by `tools/build-app.js` and committed because it is
the deployable artifact. Rebuild it after changing runtime files.
